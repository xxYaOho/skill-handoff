# Yes! Handoff Work

维护上下文卫生：既做跨 session 接力，也做工作区看板更新。让 agent 在 new session 无缝续接，零歧义。

## Quick Start

**1. 了解工作区**

通过 `scripts/handoff-init.sh`. 从它的 stdout 读取以下信息:

- `WORKSPACE_ROOT`: 工作区根目录
- `HANDOFF_FILE`: 索引文件路径
- `HANDOFF_DIR`: 交接文档存放目录
- `CREATED_INDEX`: 本次是否新建了索引

脚本失败时不要自行猜测路径, 把 stderr 原样告知用户后停止.

**2. 确认模式**

在上下文几乎没什么有效信息时, 进入**接力模式**. 参考 `HANDOFF.md` 开头 blockquote.

- 若索引含 **≥2 个** 课题组 (`## T<N>:`): **先**用宿主的 AskUserQuestion（或等价 ASK）列出各代号 + 一句话描述, 并提供「只看全局 / 我自己说」出口; **用户选定前**不得深读各组交接文档、不得复验某一组、不得自行开工. ASK 焦点是跟进哪条活跃课题, **不**催归档.
- 仅 0–1 个课题组时, 按 blockquote 直接恢复与复验.

而其它情况下, 从上下文判断是轻量还是全量交接.

**收尾必轻量**: 会话到达交付、告一段落、或用户说「先这样 / 今天到这里 / 不需要接力」时, **必须**至少走轻量模式重写对应动态. 「不需要接力」不等于可以跳过索引更新 — 跳过 handoff 不是合法收尾.

- 轻量模式: 仅更新 `$HANDOFF_FILE` 的全局动态与相关课题组动态; 不新建交接文档
- 全量模式: 使用 `scripts/handoff-add.sh` 创建交接文档并写入内容; 更新 `$HANDOFF_FILE`

## Write Document

编写一份交接文档, 总结当前对话内容, 以便 fresh-agent 能够继续工作. 执行 `scripts/handoff-add.sh -n <title>` 创建文档, 从 stdout 的 `HANDOFF_DOC` 拿到路径后再写入内容. 命名规格 (时间戳, kebab-case, ASCII, ≤5 词) 由脚本强制, 不要自行拼文件名; 标题起得好坏只看它能否概括下一阶段重点.

**结构（固定小节, 结论先行）**:

1. 文首 BLUF 三行: **现在** / **下一步** / **阻塞**（短句, 一句一事）
2. `## 否决了什么` — 方案 → 为何否（可用表）
3. `## 已验证 vs 推测` — 已验证附证据; 推测明确标「未验证」
4. `## 必须由用户决定`
5. `## 现场与引用` — 路径 / sha / 未提交范围（证据外置到此或链接目标）
6. `## 建议技能` — 只列当前环境确实存在的技能; 不确定时描述能力, 不编造技能名

行文借 ASD-STE100 的**子集**: 短句、一句一事、结论先行、词义单一（「完成」只表示本轮交付成立）. 不借受控英文词表或英文词数硬杠. 不要写成会话纪要墙.

不要重复其他工件 (规格, 计划, ADR, 问题, 提交, 差异) 中已捕获的内容. 改为通过路径或 URL 引用, 并为每个引用附一句话说明它现在为什么重要. 引用必须稳定: 提交用 sha 而不是「最近一次提交」, 行号必须附内容片段.

对任何敏感信息进行脱敏处理, 例如 API 密钥, 密码或个人身份信息.

如果用户传入了参数, 请将其视为对下一阶段工作重点的描述, 并据此调整文档内容.

### 验收判据

一个完全没有本次会话上下文的 agent, 只读这份文档及其引用的文件, 能否不再追问用户就做对下一步? 不能, 就补齐缺失的部分.

> 规则
> 交接文档通常不再二次编辑. 需要续写时沿用同个标题并加版本标记: `scripts/handoff-add.sh -n <title> -s V2`, 默认 V1 无标记.

## Update

更新 `$HANDOFF_FILE` 的动态. 全量模式附上交接文档链接; 轻量模式没有新文档, 沿用现有链接或不带链接. 有课题组时, 重写**本轮涉及**的课题组动态, 并按分工更新全局动态.

动态是**当前状态的快照**, 每次交接后**整段重写**, 不是在末尾追加. 它只描述「现在」, 不描述历史 — 历史在交接文档里.

**位置**:

- 全局动态: 标题与接手说明之后, 第一个课题组标题 (`## T<N>:`) 之前的全部正文. 尚无课题组时即为文件末尾.
- 课题组动态: 该 `## T<N>:` 标题之下、交接链接之上的正文.

**索引行文（可扫）**: 全局与课题组均用短句, 宜覆盖 **现在 / 下一步 / 阻塞**（不必强制加「状态:」行）. 全局 ≤ 400 字符 (中文字符按 1 计, 含标点, 不含 Markdown 链接中的 URL). 课题组正文同等偏短, 禁止把验证链、版本身份说明、走查清单堆进索引 — 那些进交接文档.

**链接位（硬规则）**:

- 交接文档 Markdown 链接**独行**位于对应正文之后（全局在全局段末; 课题组在该组正文下）.
- 正文内**禁止**嵌入 `.tmp/handoff/` 交接链.
- 每组「当前」交接链至多 1 条. 历史/存档链若需保留, 写入交接文档的「现场与引用」, 不在看板堆多条.
- 规格 / wiki / 计划等关联引用可放在交接文档; 不要与当前交接链抢看板位.

> 规则
>
> - 顶部的接手说明 blockquote 不属于全局动态. 任何情况下都不要改写或删除它 — 它是接手方唯一的协议来源. （允许与 init 模板等价的空白规范化, 不得改行动协议含义.）
> - 删除的判据只有一条: 该描述是否还在说「现在». 已被后续交接覆盖的过期叙述要删掉; **本轮已交付**应写成「现在已交付、下一步等下一波」, 而不是从看板上抹掉课题.

## Topics Group

_课题组_

当出现两条及以上互不阻塞的工作线时, 把 HANDOFF.md 展开为全局动态 + 若干课题组. 课题组数为 0 时即为基础形态 — 二者是同一结构的两种状态, 不是两套玩法.

- **互不阻塞**: 关键限定: 若 B 在等 A 完成, 它们是同一条线的两个阶段, 不要拆.
- **粒度**: 一个课题组 = 一条可独立推进的长期轨道, 可容纳多轮短期交付. 不是一个模块, 不是一个人, 不是一个时间段.

**分工** (避免两处重复):

- 全局动态只写跨课题组的信息: 整体目标, 共享约束 (技术选型, 依赖版本), 跨课题组阻塞, 课题组之间的优先级排序.
- 课题组动态只写该课题组自己的状态与下一步.
- 同一句话不应同时出现在全局动态和某个课题组下.

首次展开时, 按上述分工把现有全局动态**切开**, 而不是整段保留在全局.

**生命周期**: 课题组只有**活跃**和**归档**两态.

- **活跃**: 创建即活跃. 课题组是长期轨道; **短期交付不是归档触发**. 交付成立时更新「现在 / 下一步」（例如下一波未定）, 课题保持活跃.
- **禁止**: 写「待归档」、把交付等同于课题结束、或在用户未要求时**主动提议归档**. 这些信号会让接手方停止跟进.
- **归档**: 仅用户明确要求（如「归档 / 这条线结束」）后执行. 先在 `$WORKSPACE_ROOT/docs/handoff-archive/T<N>-<标题slug>.md` 留下归档笔记 (课题组标题, 归档前的最新动态, 归档原因如有), 再删除 HANDOFF.md 中该节.
- **降级**: 用户归档后活跃课题组仅剩 1 条时, 主动询问用户是否并回全局动态, 恢复基础形态; 用户确认前不动结构.
- 编号只增不复用: T3 归档后新课题组用 T4. 否则历史交接文档里提到的「T3」会指向另一件事.
- 同时活跃的课题组建议 ≤ 5. 超过通常意味着目标太碎, 应当合并.

结构示例:

```
# Handoff Kanban

> 接手说明...

全局动态（短; 跨组信息）

## T1: 标题

**现在：** …
**下一步：** …
**阻塞：** …

[交接文档](.tmp/handoff/YYMMDDhhmmss-title.md)

## T2: 标题

**现在：** …
**下一步：** …
**阻塞：** …

[交接文档](.tmp/handoff/YYMMDDhhmmss-title.md)
```
