# Yes! Handoff Work

维护上下文卫生, 创建和撰写全面的交接文档, 让 agent 在 new session 无缝继续完成工作, 零歧义.

## 准备工作

执行 `scripts/handoff-init.sh`. 它会解析工作区根目录, 处理 git worktree 子区的目录链接, 并在缺失时创建 HANDOFF.md. 从它的 stdout 读取:

- `WORKSPACE_ROOT` — 工作区根目录
- `HANDOFF_FILE` — 索引文件路径
- `HANDOFF_DIR` — 交接文档存放目录
- `CREATED_INDEX` — 本次是否新建了索引

脚本失败时不要自行猜测路径, 把 stderr 原样告知用户后停止.

## 撰写交接文档

编写一份交接文档, 总结当前对话内容, 以便 fresh-agent 能够继续工作. 保存到 `$HANDOFF_DIR/YYMMDDhhmmss-<title>.md`, `<title>` 用 kebab-case, ASCII, 不超过 5 个词.

在文档中包含一个"建议技能"部分, 列出代理应调用的技能建议. 只列出当前环境中确实存在的技能; 不确定时描述所需能力, 不要编造技能名.

不要重复其他工件 (如规格说明, 计划, ADR, 问题, 提交, 差异) 中已捕获的内容. 改为通过路径或 URL 引用它们, 并为每个引用附一句话说明它现在为什么重要. 引用必须稳定: 提交用 sha 而不是"最近一次提交", 行号必须附内容片段.

对任何敏感信息进行脱敏处理, 例如 API 密钥, 密码或个人身份信息.

如果用户传入了参数, 请将其视为对下一阶段工作重点的描述, 并据此调整文档内容.

文档如何组织由你根据实际情况决定, 但无论怎么组织, 必须回答这三个问题:

1. **哪些方案被否决了, 为什么** — 防止接手方重走死路. 这是交接文档相对于 git log 唯一不可替代的信息.
2. **哪些结论已验证, 哪些是推测** — 已验证的附证据 (commit sha / 测试命令与结果 / `文件:行号` + 内容片段); 推测的明确标注未验证.
3. **哪些决策必须由用户来做** — 区分 agent 可以自行决定的与不得自行决定的.

### 验收判据

一个完全没有本次会话上下文的 agent, 只读这份文档及其引用的文件, 能否不再追问用户就做对下一步? 不能, 就补齐缺失的部分.

> 规则
> - 交接文档通常不再二次编辑. 需要续写时沿用同个标题并加版本标记, 如 `YYMMDDhhmmss-<title>-V2.md`, 默认 V1 无标记.

## 更新 HANDOFF.md

完成交接文档后, 更新 `$HANDOFF_FILE` 的全局动态, 附上交接文档链接.

全局动态是**当前状态的快照**, 每次交接后**整段重写**, 不是在末尾追加. 它只描述"现在", 不描述历史 — 历史在交接文档里.

位置: 全局动态是标题与接手说明之后, 第一个课题组标题 (`## T<N>:`) 之前的全部正文. 尚无课题组时即为文件末尾.

内容至少回答三件事: 整体处在什么阶段; 最近一次交接改变了什么; 下一步方向与当前阻塞. 每一句都可以挂交接文档链接.

> 规则
> - 顶部的接手说明 blockquote 不属于全局动态. 任何情况下都不要改写或删除它 — 它是接手方唯一的协议来源.
> - 全局动态 ≤ 400 字符 (中文字符按 1 计, 含标点, 不含 Markdown 链接中的 URL). 自查代理: 超过两个自然段就是超了, 回去压缩.
> - 删除的判据只有一条: 该描述是否还在说"现在". 工作已完成交付, 或已被后续交接覆盖, 就删掉.

## 课题组
*Topics Group*

当出现两条及以上**互不阻塞**的工作线时, 把 HANDOFF.md 展开为全局动态 + 若干课题组. 课题组数为 0 时即为基础形态 — 二者是同一结构的两种状态, 不是两套玩法.

**互不阻塞**是关键限定: 若 B 在等 A 完成, 它们是同一条线的两个阶段, 不要拆.

**粒度**: 一个课题组 = 一个可独立交付, 有独立完成定义的目标. 不是一个模块, 不是一个人, 不是一个时间段. 自检: 能否用一句"当 X 成立时本课题组关闭"来描述它? 不能说明粒度不对.

**分工** (避免两处重复):

- 全局动态只写跨课题组的信息: 整体目标, 共享约束 (技术选型, 依赖版本), 跨课题组阻塞, 课题组之间的优先级排序.
- 课题组动态只写该课题组自己的状态与下一步.
- 同一句话不应同时出现在全局动态和某个课题组下.

首次展开时, 按上述分工把现有全局动态**切开**, 而不是整段保留在全局.

**生命周期**:

- 关闭: 完成后在标题后标 `(done)`, 保留一个交接周期, 下次交接时删除.
- 降级: 活跃课题组回落到 1 条时, 可并回全局动态, 恢复基础形态.
- 编号只增不复用: T3 关闭后新课题组用 T4. 否则历史交接文档里提到的"T3"会指向另一件事.
- 同时活跃的课题组建议 ≤ 5. 超过通常意味着目标太碎, 应当合并.

结构示例:

```
# Handoff Kanban

> 接手说明...

全局动态

## T1: 标题

该课题组的最新动态

[交接文档](.tmp/handoff/YYMMDDhhmmss-title.md)

## T2: 标题

该课题组的最新动态

[交接文档](.tmp/handoff/YYMMDDhhmmss-title.md)
```

## 自检清单

- [ ] 交接文档路径为 `.tmp/handoff/YYMMDDhhmmss-<kebab-title>.md`, 时间戳为年月日时分秒
- [ ] 三个必答问题都回答了
- [ ] 所有引用的路径 / commit 真实存在
- [ ] 敏感信息已脱敏
- [ ] 全局动态是整段重写的, 只描述"现在", ≤ 400 字符
- [ ] 已过时的描述已删除
- [ ] 满足验收判据
